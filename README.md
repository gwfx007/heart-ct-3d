# 心脏CT 3D可视化医疗辅助系统（课程模拟演示版）

基于 Vue3 + VTK.js + FastAPI + MySQL 的本地医学影像演示系统。

## 环境

| 组件 | 版本 | 位置 |
|------|------|------|
| Python | 3.11.9 | 系统用户目录 `%LOCALAPPDATA%\Programs\Python\Python311` |
| Node.js | v22.23.4 | `_tools\node_extract\node-v22.23.4-win-x64` |
| MySQL | 8.0.42 | `_tools\mysql_extract\mysql-8.0.42-winx64` |
| 后端 | FastAPI | `backend\venv` |
| 前端 | Vue3 + VTK.js + Three.js | `frontend` |

## 启动 / 停止

- **启动**：双击 `start.bat`（自动启动 MySQL、后端 8000 端口、前端 5176 端口并打开浏览器）
- **停止**：双击 `stop.bat`

## 访问

- 前端页面：http://localhost:5176
- 后端接口：http://127.0.0.1:8000/api/health
- 接口文档：http://127.0.0.1:8000/docs
- 默认账号：`root` / `root`

## 功能

1. 账号登录与权限（管理员 root）
2. 病例列表管理（13 个病例、22 处病灶：P0001–P0010 模拟病例、P0023 示例病例、
   测试病例、P0001H 高清体数据病例；支持新建 / 编辑 / 删除档案）
3. 3D 视图双模式：**解剖模型**（默认，glb 三维心脏 + 冠脉/肺血管贴图，可拖动旋转与滚轮缩放，病例病灶投影标记）/
   **体数据渲染**（VTK.js 体绘制，窗宽窗位、三方向剖切、视图重置）
4. 剖切视图双模式：**三方相 3D 剖切**（默认，把 glb 模型沿轴位/冠状/矢状实时剖开）/ **2D 精读**
   （标准 MPR 轴位 / 冠状 / 矢状三切面实时联动 + 2D 测距）
5. AI 病灶分析（**真实调用大模型**）：四阶段流水线 `读取体数据 → 实测 HU 特征 → 大模型推理 → 结果校验`，
   逐病灶单独推理，返回结构化 JSON（类型、重度、阈值、层厚、置信度、所见、建议）；
   前端展示推理阶段、实时进度、已用秒数、用量 tokens，报告按病灶卡片化，并列 AI 参数 / 临床默认 / 仿真真值三方体积与误差
6. 标准 DICOM 影像闭环：一键切换 DICOM 序列 / NPY 体数据，序列可下载 zip、可导入外部 DICOM；可在列表页上传 DICOM zip 直接新建档案

## DICOM 影像数据（"从影像文件到 3D"可现场演示）

- **生成**：`backend\venv\Scripts\python.exe backend\make_dicom.py`
  （`--case 1` 只做单例，`--limit 2` 只做前两例）
- **产物**：`data\dicom\case_01 … case_10`、`case_16`、`case_17`，共 12 例，每例 192 片
  `IM0001.dcm … IM0192.dcm`，合计 2304 片
  - CT Image Storage / Explicit VR Little Endian / 16 bit 有符号 / 像素即 HU 值
  - 256×256、层厚 1.0 mm、像素间距 1.0×1.0 mm、窗位 120 / 窗宽 600
  - 中文姓名用 `ISO_IR 192`(UTF-8) 编码，RadiAnt、MicroDicom、3D Slicer 均可直接打开
  - 转换清单：`data\dicom\manifest.json`
- **页面操作**：左侧「影像数据源」可点击 **DICOM 序列 / NPY 体数据** 双向切换；
  切到 DICOM 后 3D 与 MPR 均由 `.dcm` 逐层解析重建（首次解析缓存到 `data\dicom_cache`）
- **下载**：点击「下载 DICOM 序列（zip）」，得到 192 片的 zip，解压后即可用查看器打开
- **导入**：点击「导入 DICOM（zip）」上传外部序列（≤500 MB、≤1200 片），系统当场解析渲染
- **新建档案**：档案列表页点「+ 新建档案」，填检查号 / 姓名 / 性别 / 年龄 / 检查日期 / 检查项目并上传 DICOM zip；
  系统解包 → 校验（尺寸一致、体积上限）→ 解析为体数据（存 `data\volumes`）→ 序列入 `data\dicom` → 写入 `cases` 表，
  新档案立即出现在列表，点「3D 查看」即用刚上传的 `.dcm` 渲染（新档案无预置病灶，AI 分析显示「未检出」）
- **编辑**：档案行点「编辑」可改检查号 / 姓名 / 性别 / 年龄 / 检查日期 / 检查项目，
  只更新患者信息、影像数据不动；检查号仍需全局唯一（与他人重复会被拒绝）
- **删除**：档案行点「删除」并二次确认后，病例记录、病灶（`ON DELETE CASCADE`）、
  体数据 `.npy`、DICOM 序列目录与解析缓存一并清理，`manifest.json` 同步移除该条

## 三维解剖模型（glb）

- **文件**：`frontend\public\models\heart_model.glb`（73.3 MB，150 万三角面，心脏 + 冠脉 + 肺血管树，3 张贴图）
- **渲染**：Three.js `GLTFLoader` + `OrbitControls`，页面加载即自动居中、等比缩放到视口，支持拖动旋转 / 滚轮缩放
- **切换**：左侧「3D 展示」组可切 **解剖模型 / 体数据渲染**；模型模式下窗宽窗位与剖切面板自动置灰
- **病例专属模型（多模型架构）**：按病例自动挑模型 —— 先探测
  `frontend\public\models\case_01.glb`（也认 `case_1.glb`），命中则用该病例专属模型，视图右下角提示
  「本病例专属模型」；未命中则回退通用 `heart_model.glb`，提示「通用解剖模型（无专属文件时）」。
  当前仓库只带通用模型，放 `case_01.glb … case_10.glb` 进去即自动生效，无需改代码
- **下方三图为模型实时剖切**：「剖切视图」组的默认模式（三方相 3D 剖切）不再画体数据 MPR，而是把主视图
  同一份 glb 沿三个方向实时剖切（Three.js `clippingPlanes`，三格独立 WebGL 渲染器）；切面位置随左侧
  「MPR 切面位置」的轴位 Z / 冠状 Y / 矢状 X 滑块联动。点「2D 精读 / 测量」可一键切回标准 VTK MPR 灰阶
  三视图（保留原测距功能）
- **剖面为实心**：glb 本身是开放薄壳，直接剖开只能看到空壳内壁。三格在切面处额外渲染一块「实心截面」：
  取切面两侧薄层做剪影 → 读回像素把轮廓内部填满 → 以 CanvasTexture 贴回切面，切成暗红心肌色，
  中心渐暗模拟心腔。因此剖开后看到的是实心心肌而非空腔；三格各自可拖拽旋转 / 滚轮缩放 / 双击复位
- **病例病灶标记**：解剖模型模式下，该病例已入库的病灶按解剖位置投到模型表面（黄色发光球），
  与 2D MPR 中的位置口径一致
- 说明：该 glb 为通用解剖模型（非本病例 CT 重建），病灶点位为预置模拟数据

## 数据说明

- 模拟心脏CT体积数据：256×256×192，float32（HU值），存于 `data\volumes\*.npy`
- 病灶为预置模拟数据（位置/类型/置信度），非真实临床诊断，不具备医疗效力
- 重新初始化数据：运行 `backend\venv\Scripts\python.exe backend\seed_data.py`（会重置全部病例）
- DICOM 序列由 npy 转换而来，若 `data\dicom` 被删除，启动脚本会自动重新生成

## AI 病灶分析（真实模型推理）

- **凭证**：`research\config.local.json`（`base_url` / `model` / `api_key`）。该文件含密钥，
  打包分发时由 `pack_for_other_pc.bat` 自动排除；对方电脑需按 `config.local.example.json` 自行填写。
- **后端** `backend\app\routers\analyze.py`：
  - `POST /api/cases/{id}/analyze` → 启动异步任务，返回 `task_id`
  - `GET  /api/analyze/tasks/{tid}` → 轮询阶段与结果（`stage ∈ volume|feature|llm|verify|done`）
  - `GET  /api/analyze/health` → 模型连通性自检（只回显模型名与密钥尾号）
  - `POST /api/analyze/probe` → 直接发一条测试消息，返回回复与 usage
- **计算口径**：球内体素 HU 统计（均值/中位数/P90/P95/峰值/最小/SD）与背景环（r+2～r+9）均值±SD、±3SD，
  作为提示词唯一事实来源。**分割极性分两套**：高密度灶（钙化、斑块）阈值须落在
  `[背景均值+3SD, 峰值×90%]`，取"≥阈值"为灶体；低密度灶（缺血、水肿、血栓）方向相反，
  阈值须落在 `[球内均值+3SD, (球内均值+背景均值)/2]`，取"≤阈值"为灶体。
  越界由 `_verify()` 修正并留痕，模型漏字段时按规则兜底并在报告中注明。
  **小灶层厚规则**：直径 ≤30 mm 的灶若模型给出 >2 层，一律夹到 1 层并留痕
  （跳采会整层漏掉边界——高密度灶因此过估、低密度灶因此低估，实测层厚 1/2/3/5 时
  误差约 −1.7%/+7.5%/+18.3%/+25.7%）；大灶保留模型自主。
- **体积测量**：与 `research\experiment.py` 同一套 Cavalieri 按层厚积分算法，保证网页结果与科研实验口径一致；
  低密度灶按 `≤ 阈值` 积分。
- **无标注病例（新建档案）**：`lesions` 表为空时走自动检出，两路并行：
  - 高密度路：阈值 >200 HU → 形态学开运算 → 连通域，按体积 100~15000 体素、包围盒填充率 ≥0.35、
    三向跨度比 ≤1.6、平均密度 ≥180 HU 筛形态，再用「背景环 +3SD 与灶体峰值 ×90% 是否重叠」
    剔除泡在血管腔/血池里的同密度块；
  - 低密度路：27 体素窗口局部均值当环境密度，找「环境 - 体素 > 45 HU」且 `-50 < HU < 150` 的区域，
    按体积 300~15000 体素、填充率 ≥0.35、跨度比 ≤1.6、背景对比度 ≥30 HU 筛形态。
  两路候选按显著度（峰值 / 背景对比度）统一排序，最多取 3 个交模型判读。
  卡片会标注「自动检出 · 无人工标注」与「低密度灶 · 反向阈值」，且不显示仿真真值（无独立标注可对比）。
- **结果存档与回显**：一次分析完成后，完整结果（病灶、体积、提示词与模型原文、用量）写入
  `data\ai_results\case_<id>.json`；`GET /api/cases/{id}/analyze/latest` 直接读该文件，
  不触发模型调用。前端进入 `/viewer/<id>` 时自动加载上次结果，左栏显示「… 已存档」与存档时间，
  按钮变为「重新推理」——**刷新页面、切走再切回都不必重跑模型**。同一病例再次分析会覆盖同名文件。
- **状态与病灶数**：分析完成即把 `cases.status` 置为「已分析」。档案列表的「病灶数」优先取 `lesions`
  表的人工标注条数；无标注病例取 AI 存档里的自动检出条数，并在数字后标「自动」——避免新导入的
  DICOM 档案分析完仍显示 0 个病灶、状态停在「待分析」。
- **病灶落库（source 字段）**：`lesions` 表新增 `source` 列区分来源——`manual` 为人工标注（临床比对真值，
  AI 分析只读不改），`auto` 为 AI 自动检出（无人工标注的病例由算法给出）。每次分析先把该病例旧的
  `auto` 记录清掉再写入，重复分析不会累积重复病灶；因此刷新页面、重开档案后 3D 页仍标得出 AI 病灶，
  三维标注颜色也可区分：琥珀色＝人工标注，青色＝AI 自动检出。
